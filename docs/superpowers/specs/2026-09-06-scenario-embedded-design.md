# 场景内嵌重构设计：场景作为规则/重定向的内部分组维度

- 日期：2026-09-06
- 状态：已确认（用户逐节确认后定稿）
- 前置：第二期「规则引擎扩展」已合入 master（独立「场景」标签页 + Scenario/RedirectRule.scenario 字段）

## 1. 背景与目标

第二期的场景是独立标签页：用户须先建场景，再到规则/重定向编辑器里挂场景，列表页看不到分组关系，割裂且难用。

本次重构目标：

1. 场景不再是独立标签页，而是规则页与重定向页内部的**分组展示维度**（用户选择：分组小节形态）
2. 初始场景「默认」：**不可删除、不可改名、可开关**（用户修订后口径）
3. 其他场景：可开关、可改名（级联更新引用）、可删除（删除时转移条目）
4. 支持场景排序拖拽；支持规则/重定向条目拖拽到另一场景
5. 重定向优先级高于规则（管道现状）显性化；mock 命中为跨场景全局优先级取第一个命中（现状显性化）

## 2. 非目标

- 不做批量移动条目（删除场景时的转移除外）
- 不做场景颜色/图标/重命名外的场景元数据
- 不做场景内独立优先级空间（优先级始终全局）
- 不引入拖拽库（用原生 HTML5 DnD）

## 3. 用户决策记录

| 问题 | 决策 |
| --- | --- |
| 展示形态 | A. 分组小节（非顶部筛选、非「全部」平铺） |
| 默认场景语义（初版） | 曾选「可删（删前转移）」，后修订为**不可删不可改名、可开关** |
| 管理入口 | A. 组头内联（非集中弹窗） |
| 新增 | 场景排序拖拽 + 条目跨场景拖拽 |

## 4. 信息架构与交互

### 4.1 标签页

- `App.tsx` 移除「场景」标签；`ScenariosPanel` 组件删除（其能力并入分组组头）

### 4.2 分组小节（规则页与重定向页同构）

每个场景渲染一个小节：

```
[⠿ 场景名] [组开关✓] (N 条) [重命名] [删除]        ← 组头（⠿ 为拖拽把手）
┌─────────────────────────────────────────────┐
│  组内表格（沿用现有列，行可拖拽）                  │
│  [+ 新建规则]（预挂本场景）                       │
└─────────────────────────────────────────────┘
```

- 组头右侧按钮：非 builtin 场景显示 [重命名][删除]；「默认」隐藏这两个按钮（IPC 同步拒绝，双保险）
- 重命名：组头原位进入输入态，回车/失焦提交
- 删除：确认弹窗含「条目去向」下拉（其他任一场景或「未分组」），确认后原子完成转移+删除
- 工具栏：规则页与重定向页均有「+ 新建场景」；提示文案：规则页「命中顺序跨场景全局按优先级，取第一个命中」；重定向页「重定向先于 Mock 规则命中，命中即短路」
- 分组顺序：**未分组（若有，置顶，无开关、不可拖）→ 场景按持久化顺序（默认初始第一）**；组内按既有优先级排序

### 4.3 未分组伪组

- `scenario === undefined` 的条目归「未分组」：纯展示分组，不落库、无组开关、条目永远生效（与现行语义一致，兼容存量数据）
- 渲染时（即存在未挂条目时）可作为拖拽目标（= 清空条目的 scenario 字段）
- 无条目时不渲染

### 4.4 条目编辑器

- `ScenarioField`（规则/重定向编辑器共用）：新建时预填「默认」（存在时），否则空（未分组）；选项含「未分组（空）」+ 全部场景

## 5. 数据模型与 main 层

### 5.1 类型

```ts
export interface Scenario { name: string; enabled: boolean; builtin?: boolean; }
```

- 「默认」：`{ name: '默认', enabled: true, builtin: true }`

### 5.2 ScenariosStore

- `load()`：读入后若不存在 `builtin` 场景则追加「默认」（含文件缺失、文件存在但被手工删掉两种情况），随后持久化
- `rename()` / `remove()`：目标为 builtin 时抛错
- 新增 `reorder(names: string[])`：按给定名字序重排数组（须为全集且无重复，否则抛错），持久化数组序
- 其余 add/setEnabled 不变

### 5.3 IPC

- `scenarios:remove(name, moveTo: string | null)`：
  - `moveTo` 为场景名 → 将 rules+redirects 中引用该场景的条目批量改挂到该场景
  - `moveTo` 为 `null` → 清引用（= 未分组）
  - 转移与删除场景一次持久化完成
- `scenarios:reorder(names)` 新增
- `scenarios:rename/remove` 对 builtin 抛错；`scenarios:add` 照旧（重名报错）
- 现有 `scenarios:rename` 的级联改名逻辑保留

### 5.4 生效与命中语义（不变，显性化）

- 条目有效 = `条目.enabled AND (场景不存在 || 场景.enabled)`（`ruleEffective` 现状不动；「场景缺失」视为生效，仅作兜底）
- mock 命中：全部有效规则跨场景按 `priority` 全局排序取**第一个命中**；场景开关关闭 ≠ 优先级让位，只是整组失效
- 管道顺序：重定向（全局优先级）→ mock（全局优先级首个命中）→ 透传上游

## 6. 拖拽实现

- 原生 HTML5 DnD（`draggable` + `onDragStart/onDragOver/onDrop`），不引依赖
- 场景排序：组头 `draggable`，拖到另一组头上释放 → 计算新顺序调 `scenarios:reorder`
- 条目跨场景：规则/重定向行 `draggable`（drag data 带 id），组头与组区域均为合法落点 → 调既有 `rulesUpdate`/`redirectsUpdate` 改 `scenario` 字段；**优先级不变**
- 「未分组」组头/区域可作为落点
- E2E 策略：HTML5 DnD 在 Playwright 中不稳定，优先用 `dispatchEvent` 模拟 dragstart/drop；若仍不稳，每行加「移动到…」下拉作为兜底入口（拖拽与菜单并存）

## 7. 迁移与兼容

- 存量 `scenarios.json`：原样保留 + 启动补种「默认」（若缺失）
- 存量规则/重定向的 `scenario` 引用：按名字匹配照旧生效；无引用的进「未分组」
- 无需数据迁移脚本

## 8. 测试计划

### 8.1 单元测试

- ScenariosStore：builtin 补种（缺文件/缺默认两种）、rename/remove 对 builtin 抛错、reorder（正常/非全集/重复名抛错）、remove 转移语义由 IPC 层测（store 只管删）
- ruleEffective：不变（回归覆盖）

### 8.2 E2E

- 规则页分组渲染：未分组置顶、默认组随后、组内「新建规则」预挂场景
- 组开关：关闭默认组 → 组内规则失效（发起请求命中透传），重开恢复
- 重命名级联：改名后规则引用同步，规则仍生效
- 删除场景 + 条目转移：转移后规则落目标组且仍生效；「默认」无删除/重命名按钮
- 拖拽：场景换序后刷新顺序保持；条目拖入另一组后 `scenario` 字段变更（必要时「移动到…」兜底）
- 重定向页同构抽查
- 受影响的既有 spec（map-local/scenarios 等）同步适配

## 9. 风险与权衡

- HTML5 DnD 的 E2E 稳定性：预留「移动到…」兜底
- 「默认」补种语义：文件存在但空数组不补种会让默认消失——本设计选择**总是补种**（默认不可删 ⇒ 用户视角它恒存在），删光其他场景后至少剩默认组，编辑器预填始终有目标
- 组头即拖拽把手与行内按钮的点击冲突：把手区域限定为⠿图标，按钮 stopPropagation
